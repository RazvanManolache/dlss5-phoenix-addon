# Lightweight FP8 implementation

`small-fp8` selects the 77-record `WEIGHTS_CC_SMALL_FP8` resource and decodes 302
tensor views through `decoder.inc` and its independent `weight_layouts.h` table.
`graph.inc` records the 31-block graph with model-specific decoder shift phases.

Regenerate the layout header from `tools/model_layouts/small_fp8.json` with
`python tools/generate_weight_layouts.py --model small_fp8`; use `--check` in
validation. The current 23 packing families and 157 parts match Original's
families; graph topology and resource selection remain model-specific. Generation
preserves the existing attributed declarations and requires no model binary.

The recording code follows the same tensor operations and naming conventions as
the original model. `build_small_fp8` reads in execution order: input stem,
encoder, global transformers, decoder, output head, then scratch planning.
The four `record_small_fp8_*` helpers keep those stages separate. Encoder stage
ranges and decoder skip pairs are explicit tables; window shifts have named
coordinates rather than positional array accesses. Comments explain the
two-block decoder phase rule and the exact output-projection slice.

The native adapter separates source-launch selection, weight-block numbering,
removed feature/publication edges, window ABI patches and tensor lifetimes.
`small_native_detail::GraphSpecializer` owns only the per-build remapping state;
`small_native_graph` remains the public entry point. One-based source launch
indices, model block IDs, kernel byte offsets and portable window shifts are
documented separately. No recovered instruction fragments are part of this
runtime code.

The portable runtime has CPU frame, temporal, control and replacement checks.
Native RTX uses the model-owned specialization at
`src/native/model/models/small_fp8/native_graph.h`: 78 launches, shared kernel modules,
model-specific shifts/grids/skips, barriers, weights and control/repeat positions.
Its actual model/bundle and injected dispatch checks run on the CPU. Subsequent
Initial GPU timing/reset/output checks covered 720p, 1080p and 4K using the same
production recorder. Those first matched NVIDIA DLSS5 results remain in
`artifacts/current/four-model-comparison/` as historical context.
Both models match corresponding NVIDIA reset/history captures byte-for-byte on
the tested fixtures. The initial mismatch report was a harness control error,
corrected before accepting parity; general game/HDR equivalence is unverified.

Fresh native checks now cover ten extents through 8K; CPU, CUDA and NVIDIA/AMD
Vulkan have two-model timing/output receipts. Vulkan now defaults to the safe
ordered feed-forward path; an explicit caller workaround is no longer needed.
See [current performance, memory and output analysis](../../../docs/benchmarks/current/README.md),
[backend support](../../../docs/SUPPORT.md) and
[usage and validation](../../../docs/SMALL_FP8.md).
Metal/HIP/SYCL have no fresh device measurements here.

The runtime readability refactor has a pre-change regression fixture at
`tests/fixtures/small_model_graph_fingerprints.json`. The corresponding
`small_model_refactor_probe.cpp` checks the complete native JSON graph and eight
portable configurations: both models, ordinary/odd extents, custom transformer
repeats, fused operations and device feature planes. It hashes every operation
field and every uploaded weight payload, including address/layout assignments.
The fixture was captured before refactoring; it is not regenerated by tests.
Intentional graph or numerical changes require a separately reviewed update.

Run it through `tools/test_model_selection.py --small-model PATH_TO_310_9_16_DLL`.
Current before/after, native dispatch, x86/x64 build and CPU frame receipts are
under `artifacts/current/small-model-support/refactor/`. Those receipts are CPU
validation, not GPU timing. The fresh current benchmark above additionally
measures the refactored native kernels and portable runtime; it does not isolate
a controlled before/after refactor speedup. These changes remain unreleased and
were not deployed to games for this refresh.
