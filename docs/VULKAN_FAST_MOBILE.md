# Optional Fast GPU arithmetic

- Set `vulkan_fast_math: true` in a Vulkan runtime configuration to request the approximate mobile path. The default remains false. Fast mode also selects the subgroup-independent compatibility path; it does not fall back to CPU.
- Status reports `vulkan_fast_math: true` and `arithmetic: "approximate-hardware"` from the actual backend. Older SDKs do not implement this option; clients should require this status acknowledgement before labelling a result Fast GPU.
- The graph, model, input resolution, working surface and requested block/pass counts stay the same. Fast shaders use native half conversions and FP32 normalization/publication arithmetic instead of software IEEE emulation. Matrix tiles use 128 invocations, two columns per invocation, fixed/unrolled reduction tiles and native FP16 partial sums over 32 terms, combined in FP32. Other operators retain their descriptor layouts and scheduling.
- Subnormal flushing, native arithmetic, contraction and FP16 accumulation can change output. Fast mode is a quality/performance experiment; it does not claim CPU-identical bytes or general perceptual/temporal equivalence.
- Exact shaders are generated separately. All 47 existing shader binaries were compared byte for byte with the Android 0.8.1-beta SDK after adding seven fast variants. Fast variants may declare Float16 arithmetic; both families reject subgroup dependencies, and the exact family still rejects Float16 arithmetic.
- Minimum device checks already require native shader float16 and 16-bit buffer storage. The optional route continues to check the remaining base Vulkan compute features. Its factory option is bit 31; the existing ABI uses an unsigned 32-bit option word.
- The physical Adreno 735 passes fast GEMM odd extents, K tails, transposed/non-transposed inputs, strided batches and unwritten padding guards on exactly representable binary-grid fixtures. Image error is measured separately against exact full-model outputs; these layout fixtures are not image-quality tests.
- `tests/test_vulkan_workgroup_spirv.py` checks capability isolation. `fp8_weights_tests` checks all 256 legacy finite E4M3 storage codes for the separately supplied accelerator experiments, including signed zero and +/-480.
- Phone timing, output-error samples and the separate QNN experiment are published with the [Android museum](https://github.com/RazvanManolache/dlss5-android-test). QNN SDK libraries and model data are not included in this runtime or source distribution.
